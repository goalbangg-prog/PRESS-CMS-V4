수정 요청을 받은 기자는 고쳐서 재검토를 요청합니다. 의견은 문장 위에 색깔로 남습니다.

AI는 초안을 돕는 도구일 뿐, 사실 확인과 최종 판단은 기자의 몫입니다. ‘출고’는 CMS 안의 상태 변경이며 외부 송고 시스템 연동은 포함하지 않습니다.

“어디를 고치죠?” 문장 위에서 확인

선택한 문장과 검토 의견을 색깔로 직접 연결합니다.

  1. 1색 일치의견 카드와 본문 형광펜 색이 같음

  3. 3의견 알림새 의견 수가 탭에 바로 표시

기사 검수제목·본문·기사 표기 지침주어·서술어 호응, 누락·중의문, 제목과 본문의 차이, 영문·국가명·수치 표기를 점검. 이유와 수정 예시 제안원문 위치에서 제안 적용·무시·확인 완료 선택

[절대 준수 원칙]
1. 기자가 답변하지 않은 사실을
   절대 상상하거나 지어내지 마라.
2. 모든 문장·수치·인용은 기자의 입력에서
   직접 근거를 찾을 수 있어야 한다.
3. 근거가 없으면 문장으로 날조하지 말고
   "[확인 필요: ○○]" 로 남겨라.
4. 질문은 한 번에 1~2개만 하고,
   이미 답한 항목은 다시 묻지 마라.

쉽게 말하면 “모르는 건 모른다고 표시하고, 기자에게 되물어라”는 약속입니다.

  1. 시작취재 메모에서 누가·무엇을·언제·어디서·왜·어떻게를 찾고, 빈 곳을 질문합니다.

  3. 부분 다시 쓰기기자 의견에 따라 제목·리드·문단 하나만 다시 씁니다.
  4. 전체 수정“더 짧게” 같은 지시를 반영하되 새 사실은 더하지 않습니다.
  5. 완성모은 사실만으로 제목 2~3개, 리드, 본문 2~4문단을 조립합니다.

01 · 본문 저장

쓸 때는 한 문서, 저장은 칸칸이

  1. 쓰는 동안 — 워드처럼 한 문서로 이어서 씁니다
  2. 저장할 때 — 문단과 사진을 한 칸씩 나눠 보관합니다 (이 한 칸을 “블록”이라 부릅니다)
  3. 다시 저장할 때 — 바뀐 칸만 골라 고칩니다

공책 한 권을 쓰지만, 보관할 땐 쪽마다 따로 끼워 두는 것과 같습니다. 덕분에 빠르고, 다른 사람이 쓴 칸을 덮어쓰지 않습니다. 입력을 멈추고 0.8초 뒤 자동 저장되며, 실패하면 다시 시도합니다.

확인할 문장을 고르면, 관련 자료와 근거를 문장 옆에 보여 주는 기능입니다. 제안 · 아직 구현 안 됨

  1. 말 고르기본문의 숫자·날짜·기관·인용문에서 확인이 필요한 말을 나눕니다.
  2. 출처 찾기공식 통계, 보도자료, 공시, 권한이 있는 취재 자료에서 후보를 찾습니다.
  3. 서로 맞춰 보기원문 구절과 날짜·대상·단위를 비교해 “뒷받침 / 어긋남 / 근거 부족”으로 표시합니다.
  4. 기자가 확인기자가 원문을 직접 열어 보고 채택할지 정합니다.
지금 있는 기능과 차이지금은 넣어 둔 자료와 초안을 글자·숫자로 비교하거나, 정해 준 주소의 본문을 가져옵니다. 웹에서 새 근거를 찾아 붙이는 기능은 아직 없습니다.
없는 출처를 만들지 않기찾지 못하면 “근거 부족”으로 남깁니다.
